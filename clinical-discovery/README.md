# Discover with confidence — first release, 20261009-1

General clinical familiarity for Faculty of Nursing, Tobruk University. This is separate from course support: no course mappings, exam scope, scores, student rankings or certificates. It does not change the existing Study Companion or simulation source files.

## Content
Seven starting topics: labels and receiving dispensed medicines; medication administration records; vial handling; tablet formulations; pulse oximeters; infusion pumps; asking for help. These are sourced educational drafts, not locally approved clinical protocols. Product-specific directions, local procedures and clinical supervision take precedence. Source links are shown within each topic. The drawings are labelled schematics, not photographs of actual devices. No prescribing or real-patient dose calculators are included.

## Private, voluntary contextual feedback
`hub-feedback/config.js` holds only the public Google Forms responder URL and context-field identifier. It must never contain the editor URL, response-sheet URL, credentials or submitted comments. Feedback is initiated only when a learner opens the link and submits the Google Form. Opening a hub topic, choosing a practice option, changing the language, and expanding the small feedback panel do not submit learning-event records. No student ID, email, name, browser fingerprint or persistent learner identifier is generated by this feature. Google and the hosting provider may process technical data under their own policies; do not claim complete technical anonymity.

Prefilled context is editable in Google Forms; treat it as respondent-supplied context, not an authenticated activity log. Duplicate or incomplete submissions may occur. Each feedback context contains fixed content metadata: topic slug, part slug, page path and release version. URL query strings, arbitrary fragments, typed questions, page-selection text and device identifiers are not copied. A missing/invalid form configuration shows a clear inactive message and never claims successful submission. The Google Form provides its own submission confirmation. All answers and individual comments stay in the owner's private Google Forms account, not in this public repository. Publishing a responder link must not publish results or editor access.

The new area has feedback at the illustration, each of three explanation parts and the practice situation. The existing student hub receives a page-level feedback link only; there is no claim of per-step coverage of the older simulations.

## What to measure
1. Number of submissions per topic, part and content version, by feedback type. These are submissions, NOT unique students or a response rate.
2. Counts of unclear explanations, questions, suggestions/corrections, technical issues and helpful-content reports. A feedback count alone cannot rank content popularity because visits are not tracked.
3. The first live feedback form deliberately has only context, feedback type and an optional comment. It does NOT collect before/after ratings. Optional familiarity ratings could be added in a later iteration; report their paired-response denominator and treat them as retrospective self-reports, not demonstrated competence, exam achievement or causal impact.
4. Internal improvement log: affected content/version, issue theme, review action, responsible reviewer, change date, new version and later feedback. Compare periods cautiously: audiences may differ and respondents are not tracked.

The owner should review responses regularly; remove inadvertently supplied identifying information before analysis or wider sharing. Do not publish raw comments, student/teacher allegations, patient details or very small identifying groups. Use thematic summaries rather than identifiable quotations. Keep ordinary complaints separate. Anonymous questions do not promise an individual reply; resolve common questions through better explanations and a reviewed aggregate “You asked; we clarified” update.

## Maintenance and release
Edit `content.js` for the topic text, `app.js` for the interactions, and `style.css` for presentation. Increment the version on substantive changes. Confirm every source and arrange local clinical review. No third-party JavaScript library or analytics service is loaded by the new area. Speech uses the browser's English speech-synthesis facility on the selected term only.

The checked-in release payload is a compressed, checksummed distribution of PUBLIC source only, used by a narrowly scoped GitHub Actions release. It is not a place for response data. `apply-clinical-discovery.py` validates allowed paths and the existing student-hub blob before first integration, and refuses to overwrite unrelated files. The first release uses the existing Pages/Jekyll publishing mechanism.
