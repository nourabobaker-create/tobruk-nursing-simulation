# Course-embedded Study Companion

Release `20261012-1` replaces the floating, programme-wide keyword chatbot with
an embedded companion on each of the 50 course views, in Arabic and English,
and inside all five English II lesson views. Search never crosses into another
course. English II lesson views additionally restrict search to the open lesson.

## Actual capabilities

- Search the loaded course explanations and, for English II, the published
  lesson passages, tables, terms, and activity reference answers.
- Translate supplied Arabic/English text inside the course using MyMemory’s
  public GET API. Translation alone sends text off the device. The visible
  notice identifies the provider, and requests omit credentials and referrers.
  Text is capped at 2,000 characters before sending, split below the provider’s
  500 UTF-8 byte request limit, timed out, and never silently truncated.
- Read text and results with the device’s speech synthesis, with language,
  speed, and stop controls. Device voices can differ in availability/quality.
- Extract key sentences from supplied text. This is an extractive summary,
  not a generated interpretation.
- Compare an answer’s vocabulary against an explicit, editable reference.
  Show reference ideas to revisit and flag negation/numerical differences.
  **No semantic correctness verdict or grade is returned.** Supplementary
  course explanations are distinguished from an activity’s answer key.
- Display course-specific Library links, all 600 curriculum topic mappings,
  and preserved documented support/coverage limits. Links do not imply that
  full books have been ingested. Students can paste their chosen passage.

Source metadata is generated by `python study-companion/build-source-index.py`
from the existing Library catalogue. There are 972 distinct resources in the
course mappings. No books are downloaded by this build, and the index explicitly
declares `full_text_imported: false`.

## What a full AI companion still requires

GitHub Pages serves static files. No inference provider or API key is currently
configured. Free-form reasoning, faithful generative summarisation, and semantic
answer review need a server-side model service, plus ingested source passages
with identifiers and provenance. A frontend API key would be public and must
never be added to this repository.

An institutional service can expose a same-site HTTPS POST endpoint receiving
`course_id`, `lesson_id`, `task`, `question`, `student_answer`, `reference_answer`,
and selected `passages` with IDs. It should return a response and only citations
to those supplied passage IDs. The service must refuse unsupported answers,
avoid official grades, enforce request/rate limits, and keep provider credentials
on the server. It must be enabled explicitly before any text or answer is sent.
The current tools do not claim that this service is present.

## Verification

`node --test study-companion/tools.test.cjs` checks course confinement, unknown
queries, preservation of text and numbers, negation, and source mapping integrity.
DOM checks exercise all course routes, both language variants, English II lesson
navigation, the pasted-text tools, translation failure paths, and source loading.
Live checks verify the deployed UI and a non-sensitive translation.

The English II service worker caches only known same-origin application assets.
It does not cache translation queries/responses, and it only deletes its own
outdated caches during activation.
