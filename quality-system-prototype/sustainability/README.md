# اختبار المؤسسية والاستدامة التشغيلية

كلية التمريض، جامعة طبرق — مسودة تفاعلية 0.4، بتاريخ 3 أكتوبر 2026.

## الغرض والحالة

تجربة طريقة بسيطة للتحقق من أن العمل محفوظ للمؤسسة ويمكن لمن يأتي لاحقًا مواصلته. نختبر العملية وإرشاداتها، لا كفاءة الموظفين، ولا ننتج درجة اعتماد.

هذه وحدة عاملة **محليًا داخل المتصفح** مرتبطة بالنموذج التجريبي لإدارة الوثائق. ليست تشغيلًا مؤسسيًا محميًا أو نظام استقبال مركزيًا. لم تُنقل إليها سجلات تقييم حقيقية، ولا تتضمن مصادقة أو صلاحيات خادم.

## الوصول

من المساحة الأم `quality-system-prototype/` اختر «اختبار المؤسسية والاستدامة». يظهر المدخل في شاشة البداية والقائمة وبداخل صفحة الوثائق. المسار المباشر `quality-system-prototype/sustainability/`.

أُضيفت بطاقة النموذج إلى فهرس الوثائق برمز مقترح `NUR-FRM-SUS-001` وحالة **مسودة**، وأُضيف دور تجريبي باسم «قسم التوثيق والأرشفة». اختيار الدور لا يمنح صلاحية فعلية.

## الاستخدام

1. أنشئ سجلًا لعملية واحدة: اسمها، الجهة المسؤولة وظيفيًا، تاريخ التقييم، الأهمية، وتكرار التحديث. الأمثلة اختيارية وقابلة للتعديل.
2. أجب عن 16 سؤالًا ضمن ثمانية محاور. لا تُملأ الإجابات تلقائيًا. «لا أعرف» ليست نجاحًا.
3. اربط شاهدًا برمزه أو مرجعه، أو أرفق ملفًا تجريبيًا غير حساس. يمكن ربط شاهد واحد بعدة أسئلة دون رفعه مرارًا. مراجعة الشاهد تحتاج نتيجة وصفة وظيفية وتاريخًا وملاحظة تحقق.
4. سجّل تجربة تسليم لمهمة صغيرة: المهمة، صفة المنفذ، مرجع الصلاحية القائم، تاريخ التجربة، النتيجة وشاهدها. لا يمنح الاختبار تكليفًا أو تفويضًا ولا يفترض بديلًا قانونيًا تلقائيًا.
5. اقرأ التشخيص وأكمل المسؤوليات المقترحة والمواعيد ومراجع إجراءات المعالجة. يمكن نسخها إلى سجل التحسين التجريبي الموجود. إعادة النسخ لا تنشئ الإجراءات نفسها مرتين، ولا تُحدّث الإجراءات المنسوخة سابقًا تلقائيًا.
6. بعد المعالجة أنشئ إعادة اختبار مرتبطة. يبقى السجل السابق، بينما تبدأ الإجابات والشواهد والنتائج في السجل الجديد فارغة.

الإدخال والحفظ المنظم والأرشفة من مسؤولية قسم التوثيق والأرشفة. إعداد المحتوى وصحته ومراجعته واعتماده بحسب اختصاصات جهاته. حقول المراجعة متاحة تقنيًا لكل من يفتح النموذج التجريبي؛ ليست صلاحيات محمية.

## قواعد التشخيص

- الفجوة الصريحة في الملكية أو وصول المخوّل أو قابلية الاسترجاع تظهر خطرًا مرتفعًا ولو كانت بقية الإجابات إيجابية.
- النقص الصريح أو الحاجة إلى تدخل القائم السابق أو تعذر التسليم يكشف اعتمادًا أو فجوة تشغيلية.
- الإجابات الناقصة لا تنتج تقييمًا مكتملًا. الإجابات الجزئية والمجهولة تظل نقاط معالجة أو تحقق.
- الإجابات الإيجابية وحدها لا تنتج «مؤسسية ومستدامة». يلزم اكتمال الشواهد ومراجعاتها وتجربة مستقلة ناجحة موثقة، وكل ذلك يبقى ضمن المراجعة التجريبية.
- التاريخ المستقبلي أو غير الصحيح لا يصلح تاريخًا لمراجعة شاهد أو تجربة تمت.
- وضع الإجراء «قُدم للتحقق» لا يغلق الفجوة تلقائيًا ولا يغير الإجابة الأصلية.

القواعد هنا من تصميم المسودة وليست معيارًا رسميًا أو أوزانًا صادرة عن جهة اعتماد. هذه النواة المشتركة ذات 16 سؤالًا لا تدّعي استيراد البنوك التخصصية أو ملفات النماذج السابقة ذات الصيغ الأخرى. لم تُحذف النماذج السابقة.

## الحفظ والمرفقات والتصدير

- السجلات: مفتاح `tobruk-sustainability-v04` في `localStorage`.
- المرفقات الفعلية: قاعدة `tobruk-sustainability-files-v04` في `IndexedDB`.
- لا ترسل الوحدة إجابات أو ملفات إلى خادم. ملفات المصدر العامة في GitHub لا تستقبل إجابات المستخدم.
- حد الملف 5 ميغابايت، ومجموع مرفقات السجل 20 ميغابايت. الأنواع: PDF وDOCX وXLSX وCSV وTXT وPNG وJPG/JPEG. لا تُعرض محتويات الملفات داخل الصفحة.
- التصدير ينتج JSON يتضمن السجل والملفات الفعلية. الملف غير مشفر؛ لا تضع فيه معلومات حساسة.
- الاستيراد يضيف نسخة بمعرف جديد ولا يستبدل الأصل. تُعاد مراجعات الشواهد إلى بانتظار التحقق، وتُنقل المرفقات إلى معرفات محلية جديدة.
- الاستيراد يدعم فقط صيغة `tobruk-sustainability-package` الإصدار 1؛ ليس استيرادًا عامًا لكل ملفات JSON أو للنماذج الأقدم.
- قد تضيع البيانات عند مسح بيانات المتصفح أو تغيير الجهاز. التصدير اليدوي ليس بديلًا عن النسخ المؤسسي التلقائي.
- عند امتلاء التخزين أو تعارض تبويبين يتوقف تأكيد الحفظ ويظهر التنبيه؛ صدّر العمل قبل الإغلاق. لا يُستبدل مخزن غير مقروء بصمت.
- إعادة ضبط النموذج الأم لا تمسح سجلات هذه الوحدة، لأنها في مساحة تخزين مستقلة. المقارنة والسجل المحلي قابلان للتعديل وليسا سجل تدقيق محصّنًا.

## الربط مع المساحة الأم

`../sustainability-link.js` يضيف الروابط وبطاقة النموذج فقط، دون استبدال بيانات المساحة القائمة. أمر «نسخ إلى سجل التحسين التجريبي» يضيف بطاقة لسجل التقييم وإجراءات جديدة إلى `tobruk-qms-prototype-v01` مع معرف المصدر. يلزم إعادة فتح المساحة الأم لعرض التغييرات. لا توجد إشعارات أو تكليفات أو موافقات رسمية ناتجة عن هذا النسخ.

## لمن يتولى الصيانة بعدنا

- `core.js`: الأسئلة والقواعد والتحقق من التواريخ وتنظيف الاستيراد.
- `ui.js`: النماذج والحفظ المحلي والمرفقات والتصدير والاستيراد والربط والطباعة.
- `index.html`: الهوية والتنسيق وحدود الاستخدام.
- `core.test.cjs`: اختبارات القواعد ببيانات اصطناعية؛ شغّل `node --test quality-system-prototype/sustainability/core.test.cjs` من جذر المستودع.
- `.github/sustainability-browser.cjs`: اختبار متصفح معزول بملفات اصطناعية؛ لا يعمل على ملفات المستخدم أو حساباته.
- `.github/workflows/sustainability-checks.yml`: اختبارات تلقائية عند تغيير الوحدة.

لا توجد مفاتيح سرية أو كلمات مرور في هذه الملفات. لا تغيّر أسماء مفاتيح التخزين لإصلاح مشكلة دون خطة نقل، حتى لا تبدو السجلات السابقة مفقودة. أي تغيير في قواعد التشخيص يحتاج مراجعة الاختبارات ووصف الإصدار.

## ما يلزم قبل التشغيل المؤسسي

الحفظ المشترك تحت إدارة المؤسسة، حسابات ومصادقة فعلية، صلاحيات مفروضة على الخادم، مسؤولية تشغيل وإدارة حسابات موثقة، نسخ احتياطية وتجارب استرجاع، سجل تغييرات محمي، وسياسة ملائمة للبيانات والاحتفاظ بها. يظل رفع السجلات الحساسة إلى هذه النسخة العامة غير مناسب حتى تحقق هذه المتطلبات.

لا يعلن هذا الإصدار أن هذه المتطلبات نُفذت. جرى بناء المسودة لتجربة الأسئلة وسير العمل مع الحفاظ على وضوح هذا الفصل.
